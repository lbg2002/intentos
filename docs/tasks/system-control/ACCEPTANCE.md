# 开发验收与证据矩阵

## 环境分层

| 层 | 环境 | 必须验证 | 不可替代的结论 |
| --- | --- | --- | --- |
| L1 | 普通开发容器 | 格式、clippy、Schema、解析、审批摘要、存储迁移、模拟适配器 | 不证明真实内核隔离或桌面支持 |
| L2 | 可恢复 Ubuntu VM，userns/bwrap 或已验证 Landlock | 真实文件/网络/进程隔离、超时取消、恢复、特权拒绝 | NodePermission 通过不能替代 OS 隔离 |
| L3 | GNOME 登录会话，Wayland/X11 分列 | 软件动作、GTK/GNOME/Web、一致审批、快捷键、焦点、读屏 | 声明可用或仅 smoke 通过不等于业务完成 |
| L4 | 独占参考设备，Release | 安装升级、长时稳定、延迟、内存、电池/索引 | Debug/并发构建数据不能证明发布 SLO |

平台优先：Ubuntu 24.04 为主验收，22.04/26.04 独立兼容验证；版本兼容声明只覆盖实际验证组合。禁止将整个产品依赖于开发工作区的绝对路径。

## 必须覆盖的行为

| 编号 | 任务包 | 场景 | 通过条件 |
| --- | --- | --- | --- |
| V01 | 03 | 审批后替换原脚本 | 执行批准的冻结字节或明确拒绝；绝不执行替换内容 |
| V02 | 03 | 参数/cwd/解释器/网络/写目录被修改 | digest 不匹配，无副作用 |
| V03 | 03 | nonce 重放/过期/跨会话 | 全部拒绝，旧审批不能恢复为通用授权 |
| V04 | 03/04 | 源脚本和 artifact symlink/路径竞争 | 授权外数据不被读写，错误可解释 |
| V05 | 03 | BASH_ENV/ENV/LD_PRELOAD 注入 | 未批准初始化不执行，环境不泄露凭据 |
| V06 | 04 | 子孙进程、超时、无限输出 | 资源受限，取消后无后台继续写入 |
| V07 | 04 | executing/applied 阶段崩溃 | 恢复待核验，不重复修改或网络发送 |
| V08 | 05/06 | 动作已发送但未验证 | 不显示完成，不切换渠道重复产生副作用 |
| V09 | 06 | 路径含空格/中文、多个实例、目录名误导 | 正确软件/资源身份，无关进程不受影响 |
| V10 | 06 | 不同版本/打包格式/桌面权限 | 实际能力与矩阵一致；不可观察时明确说明 |
| V11 | 07 | 未批准/OS 未认证/参数越界 | 特权动作不执行；用户取消认证不会被自动重试 |
| V12 | 07 | 设置变更与撤销时有外部修改 | 读回准确，冲突不覆盖新值 |
| V13 | 08 | 管道失败、重定向越界、条件链 | pipefail/依赖语义正确，未知副作用不重放 |
| V14 | 09 | UI 显示与实际执行对象不一致 | 测试必须拒绝或暴露错误，不产生误导审批 |
| V15 | 03/09 | 脚本含凭据，隐私模式 | SQLite/JSON/log/event/export 无未经允许原文；执行内容未因脱敏变形 |
| V16 | 02 | 干净安装、升级中断、任意 cwd | 服务/资源路径正确，可恢复，旧数据保留 |
| V17 | 10 | 支持范围内完整用户任务 | 验证最终目标，列明未完成子目标，不以退出码代替 |

测试要有正向对照：网络隔离测试先建立宿主真实监听端口；文件越界测试先确认 fixture 可读；权限拒绝测试还须证明授权内动作在合格环境可完成，避免“一律拒绝”的伪成功。

## 标准命令

在当前仓库工具链/依赖就绪后执行，日志放 `work/`，发布证据放 `docs/validation/`。先运行针对性测试，再运行必需全量；源码改变后选择受影响套件补验，不反复并发编译污染性能结果。

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
env -u DISPLAY -u WAYLAND_DISPLAY cargo test --workspace --no-fail-fast -- --test-threads=1
cargo build --release --workspace
./target/release/intentosctl eval --corpus eval/intents/v0_1_shell_300.json --report-out work/system-control-eval.md
```

先创建 `work/`；真桌面环境另运行：

```bash
/usr/bin/python3 desktop/settings/intentos-settings.py --smoke-ui
/usr/bin/python3 desktop/gtk-fallback/intentos-launcher.py --smoke-ui
```

若脚本返回 skipped，记录未执行，不能计作 UI 通过。必须增加对应包的真实行为测试，不能只跑上述历史套件。

## 性能与用户体验门槛

沿用顶层规划的候选 SLO，在 SC-01 建立基线后冻结：热浮窗 P95≤150ms；候选 P50≤12ms/P95≤30ms；首次任务反馈 P95≤150ms；确定性本地控制 P95≤300ms（单列应用冷启动与验证）；取消 UI P95≤100ms、受控进程停止目标≤2s；守护进程空闲 RSS≤80MiB、10分钟 CPU 平均<0.5%单核。资源探测冷缓存单列，不隐藏首轮耗时。

风险判定 P95≤10ms 是建议目标，不含首次扫描；必须报告全链路首轮时间。输出采样量、负载、缓存状态、硬件、内核、桌面、SHA、构建模式，性能测试不得与编译并发。

## 完成门槛

- 代码实现、错误与恢复语义、Schema/RPC 兼容、测试证据、文档和 GitHub 提交齐全。
- 至少一个正常成功和一个拒绝/失败场景通过；安全敏感包须完成对应 L2/L3 验证。
- 状态可为 implemented_unverified，不能跳过真实环境门槛直接 verified。blocked 不代表代码未写，也不代表已验收。
- 未通过基础安全能力的工作包保持默认关闭；后续独立工作可以继续。
- 不必为文档或低影响调整添加镜像式测试；对执行与权限必须测试可观察行为。
